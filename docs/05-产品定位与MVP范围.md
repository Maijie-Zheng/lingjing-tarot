# 灵境 · 产品定位与 MVP 范围

> 文档状态：V1.0 初稿 | 最后更新：2026/06/08 | 作者：@Y9000 + AI协助分析
>
> ⚠️ 这是整个项目最重要的决策文档——它定义了 V1 到底做什么、不做什么、为什么。

---

## 一、产品定位

### 定位陈述（标准 PM 格式）

> **对于** 在深夜感到焦虑或纠结的年轻人，
> **他们需要** 一个私密的、被理解的方式帮自己梳理情绪和方向，
> **灵境是** 一个 AI 驱动的塔罗解读 Web 应用，
> **它能** 通过仪式感十足的抽牌体验 + AI 深度个性化解读，让用户感到"被读懂"，并得到可落地的行动建议。
> **不同于** 抖音上被动的"大众占卜"（太泛）、真人大师咨询（太贵）、免费塔罗 App（太模板化），
> **灵境** 是第一个同时做到"仪式感 × AI 个性化 × 中文文化理解"的产品。

### 一句话总结

> **灵境 = 有仪式感的 AI 塔罗，让你感觉被理解，而不仅是"被算"。**

### 品牌调性

| 维度 | 灵境的风格 |
|------|----------|
| **声音** | 温柔但不说废话、专业但不冷漠——像"懂塔罗又关心你的朋友" |
| **视觉** | 深紫 + 金色 + 星空，神秘感与温暖并存 |
| **体验** | 慢一点，有仪式感——不是"获取信息"，而是"进入对话" |
| **情感** | 让用户离开时比进来时更平静、更有力量 |

## 二、MVP 核心原则

做 MVP 最容易犯的错误是"再加一个小功能"。这里列三条铁律：

| 原则 | 含义 |
|------|------|
| 🎯 **为"深夜的小雨"设计** | 每做一个功能决策，想象凌晨 11 点在床上的小雨——她会用吗？她会困惑吗？ |
| 🔪 **狠心砍功能** | "以后可以做" = "现在不做"。MVP 不是功能少，是**精准**。 |
| ✨ **少但精，不是少但糙** | 3 个做到极致的功能 > 10 个做到 60 分的功能 |

## 三、MVP 功能范围（MoSCoW 分析）

### Must Have（P0 — 没有就不是灵境）

| # | 功能 | 描述 | 用户价值 |
|---|------|------|---------|
| 1 | **问题输入** | 用户输入自己的问题（文字），提供引导示例 | 这是 AI 个性化的基础——不知道问题就谈不上"懂你" |
| 2 | **三牌牌阵抽牌** | 洗牌动画 → 用户选 3 张 → 翻牌动画（代表过去/现在/未来） | 仪式感的核心载体，3 张牌是最经典的塔罗格式 |
| 3 | **AI 个性化解读** | 根据用户问题 + 三张牌 + 位置含义 → 生成贴合问题的解读 | 🔥 灵境的灵魂——解读必须让用户觉得"它懂我" |
| 4 | **行动建议** | 基于解读给出 2-3 条具体的、可落地的建议 | 从"知道了"到"回去试试"——把情绪价值转化为行动 |
| 5 | **分享卡片** | 一键生成精美的解读结果图片，可分享到微信/朋友圈/小红书 | 🔥 获客引擎——每张卡片 = 一个广告位 |
| 6 | **历史记录（本地）** | 用户的解读记录保存在浏览器本地，可回看、可删除 | 留存+隐私（不需要登录也能保存） |

### Should Have（P1 — 有最好，实在来不及可以砍）

| # | 功能 | 描述 |
|---|------|------|
| 7 | **问题引导/示例** | 输入框下方显示 3-5 个常见问题模板（"他对我什么感觉？""该不该跳槽？"） |
| 8 | **洗牌音效 + 背景音乐** | 轻柔的背景音 + 翻牌音效，增强仪式感 |
| 9 | **解读结果页面动画** | 文字逐段出现，制造"被慢慢解读"的感觉 |
| 10 | **隐私提示** | 首次使用时告知"你的问题只保存在你的手机里，不上传服务器" |

### Could Have（P2 — V1 不做，V2 考虑）

| # | 功能 | 为什么 V1 不做 |
|---|------|--------------|
| 11 | 多种牌阵（单牌/凯尔特十字等） | 三牌牌阵足够支撑 MVP 体验，多牌阵增加选择负担 |
| 12 | 追问对话 | AI 先一次性把解读说完，追问的逻辑复杂度高很多 |
| 13 | 每日塔罗推送 | 需要推送系统，V1 不做 |
| 14 | 正逆位显示 | 增加认知门槛，对小白用户不友好 |
| 15 | 登录/注册 | MVP 不设登录，用本地存储，降低使用门槛 |

### Won't Have（明确不做 — 防范围蔓延）

| # | 功能 | 为什么不做 |
|---|------|----------|
| 16 | 社区/动态 | V4 的事，MVP 聚焦核心体验 |
| 17 | 真人达人咨询 | 灵境是 AI 产品，不是真人平台 |
| 18 | 星座/八字/其他玄学 | 聚焦塔罗，一把刀磨到最利 |
| 19 | 付费/会员 | V3 的事，先验证用户喜欢用 |
| 20 | 原生 App（iOS/Android） | MVP 做 Web App，一套代码全平台可用 |
| 21 | 国际化/英文版 | 先把中文体验做到极致 |

## 四、MVP 用户流程（核心路径）

### 主线流程

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌──────────┐    ┌─────────┐
│  首页    │ → │ 输入问题 │ → │ 洗牌选牌 │ → │ AI 解读  │ → │ 结果页  │
│ 氛围入口 │   │ 引导示例 │   │ 3张翻牌  │   │ 逐段呈现 │   │ 行动建议 │
└─────────┘    └─────────┘    └─────────┘    └──────────┘    └────┬────┘
                                                                    │
                                                    ┌───────┬───────┤
                                                    ↓       ↓       ↓
                                                📷 分享  💾 保存   🔄 再算一次
```

### 每一步的设计目标

| 步骤 | 页面 | 设计目标 | 用户情绪 |
|------|------|---------|---------|
| 1 | 首页 | 建立氛围，降低进入门槛 | "好美...我试试" |
| 2 | 问题输入 | 引导用户说出心事 | "我要问什么好呢？" → "对，就是这个问题" |
| 3 | 洗牌选牌 | 营造仪式感，建立期待 | 🤲 "就这三张了" |
| 4 | 翻牌 | 紧张 + 期待 + 惊喜 | 😯 "是什么牌？" |
| 5 | AI 解读 | 让用户觉得"被读懂" | 🥹 "它怎么知道的..." |
| 6 | 结果 + 建议 | 落地行动，收束体验 | 💪 "好，我试试" |
| 7 | 分享/保存 | 传播 + 留存 | 📤 "发给闺蜜看看" |

## 五、关键设计决策（含决策理由）

### 决策 1：为什么是 3 张牌，不是 1 张或 10 张？

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 1 张牌 | 极简 | 信息量太少，解读像"运气签" | ❌ |
| **3 张牌** | 经典过去-现在-未来框架，信息量刚好 | — | ✅ |
| 5+ 张牌 | 丰富 | 认知门槛高，小白困惑 | ❌ |

> **决策**：MVP 只用三牌牌阵（过去-现在-未来）。这是塔罗最经典的格式，用户不需要"懂塔罗"也能理解。

### 决策 2：用户选牌还是随机发牌？

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 随机发牌 | 简单 | 用户没参与感，"跟抽签一样" | ❌ |
| **手动选牌** | 参与感强、仪式感来源 | 实现稍复杂 | ✅ |

> **决策**：用户在洗牌后的牌背中手动点选 3 张。这个"选"的动作是仪式感的关键——用户觉得"是我选的，所以解读是关于我的"。

### 决策 3：为什么不做登录？

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 要登录 | 跨设备同步、用户数据 | 流失率 +30-50%，"算个塔罗还要注册？" | ❌ |
| **不要登录** | 零门槛、隐私感强 | 用户换设备记录丢失 | ✅ |

> **决策**：MVP 不做登录。塔罗是高隐私场景——用户写的"他对我什么感觉"不想跟任何账号绑定。用浏览器 localStorage 存记录，并明确告知"只存在你的手机里"。

### 决策 4：Web App 还是小程序？

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 微信小程序 | 分享方便、微信生态 | 审核风险（玄学内容）、开发约束 | ❌ |
| **Web App** | 无审核、全平台、链接即用 | 需要用户主动打开 | ✅ |

> **决策**：MVP 做 Web App。塔罗内容在国内可能面临平台审核风险，Web App 不受 App Store/小程序审核限制。而且"一个链接就能用"是最低的获客门槛。

## 六、MVP 不做什么——防范围蔓延清单

这是给未来的自己看的。当开发过程中你突然想"要不再加一个 XX 功能"，回来看这张表：

| 诱惑 | 为什么不做 | 什么时候做 |
|------|----------|----------|
| "要不再加一个感情/事业/学业分类？" | 分类增加选择负担，AI 自己能从问题里判断 | V2 |
| "要不再加一个星座选填？" | 塔罗和星座是两套体系，混在一起不伦不类 | V2 |
| "要不再加一个语音输入？" | 文字输入足够，语音增加开发复杂度 | V3 |
| "要不再加一个用户头像/昵称？" | 没有登录，做这个没意义 | V2（跟登录一起） |
| "要不再加一个点赞/评论？" | 灵境不是社区，是私密体验 | 永远不做 |
| "要不再加一个付费去广告？" | 先验证用户想要这个产品，再想赚钱 | V3 |

## 七、MVP 成功指标

### 核心验证问题

> **用户觉得 AI 解读"懂自己"吗？**

这不是"有没有人用"，而是"用的人有没有感觉被理解"。

### 关键指标（MVP 阶段）

| 指标 | 定义 | 目标（怎么算"成功"） | 怎么测量 |
|------|------|-------------------|---------|
| **解读完成率** | 输入问题 → 看到解读结果 | > 70% | 埋点 |
| **分享率** | 看到结果 → 点了分享 | > 15% | 埋点 |
| **复访率** | 7 天内再次使用 | > 30% | localStorage 时间戳 |
| **净推荐值（NPS）** | "你多大程度上愿意推荐给朋友？" | > 0（正向就成功） | 解读结果页底部小问卷 |

### 不要看什么

| 指标 | 为什么 MVP 不看 |
|------|---------------|
| DAU/MAU | MVP 没有推送，日活没意义 |
| 收入 | MVP 不做付费 |
| 留存曲线 | MVP 样本太小，看趋势即可 |

## 八、从 MVP 到 V2 的演进路径

```
V1（MVP）              V2                    V3                   V4
抽牌+解读+分享    →   +登录+星座+推送   →   +多牌阵+付费    →   +社区
Web App              账号系统              深度服务             UGC
验证"被理解"         验证"愿意注册"        验证"愿意付费"      验证"愿意互动"
```

每个版本只验证一个问题。不跳过、不合并。

## 九、结论

### 灵境 MVP 的一句话定义

> **一个 Web 网页：输入问题 → 选 3 张牌 → AI 解读 + 行动建议 → 分享精美卡片。**
>
> 没有登录，没有付费，没有复杂功能。
>
> 只验证一件事：**用户是否觉得被 AI 理解。**

### MVP 需要开发的东西

| 模块 | 内容 | 技术难度 |
|------|------|---------|
| 🏠 首页 | 氛围背景 + 标题 + 开始按钮 | 🟢 低 |
| ✍️ 问题输入 | 输入框 + 引导示例 | 🟢 低 |
| 🃏 抽牌交互 | 洗牌动画 + 牌背展示 + 选牌 + 翻牌 | 🟡 中 |
| 🤖 AI 解读 | 调用 LLM API + Prompt 工程 | 🟡 中 |
| 📋 结果页 | 逐段动画 + 行动建议 | 🟢 低 |
| 📤 分享卡片 | Canvas 生成图片 | 🟡 中 |
| 💾 历史记录 | localStorage 存取 | 🟢 低 |

**总共 7 个模块，3 个简单、4 个中等——一个 Web 前端同学 1-2 周可以完成，Vibe Coding 工具 2-3 天。**
